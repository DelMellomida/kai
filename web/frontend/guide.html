Devcon Face Tracking Robot

Setup guide for building a face-tracking robot head using a Jetson Orin Nano, Arduino Uno, and SG90 servo motors. Beginner-friendly — step by step.

🔄 Pan — left / right ↕ Tilt — up / down 👄 Jaw — mouth open / close
🤖

What is this?

The Devcon Face Tracking Robot uses a camera and Google MediaPipe AI to find a human face in real time. It then sends commands to servo motors so the robot head always faces the person in front of it — left, right, up, down — and opens a jaw servo whenever the person opens their mouth.

It also detects deliberate gestures (nod, shake, approach, retreat, mouth open/close) and fires a serial event to the Arduino so you can trigger LEDs, sounds, or any other hardware reaction.

⚡

Don't power servos from the Arduino 5V pin — the Arduino gets its 5V from USB which is limited to ~500 mA total. Three servos moving under load can easily exceed that and cause the Arduino to reset or behave erratically. Use one of the options in the Wiring section instead.

Powering the servos — pick one option

OptionHowGood when…Watch out for…
Jetson GPIO 5V ⭐ Servo red wire → Jetson pin 2 or 4
Servo GND → Jetson GND + Arduino GND		 You already have the Jetson set up and want the simplest wiring Your power adapter must be beefy enough — Jetson under load already draws 8–15 W. Fine on the standard 19 V dev kit adapter.

Bridge GND to Arduino GND		 You have 3 servos under heavy mechanical load, or want power fully isolated One extra cable; needs a shared GND wire back to Arduino
Arduino 5V pin Servo red wire → Arduino 5V pin 1 servo, light load, just testing USB limits total current to ~500 mA. Multiple servos moving simultaneously can brown out the Arduino and cause resets or twitching.
💡

Shared ground is critical regardless of which power option you use. The servo GND wire and the Arduino GND must be connected together. Without a common ground the signal wire has no reference and the servo behaves randomly.

Software setup

  1. 1
    Install Python libraries
     terminal
    pip3 install opencv-python mediapipe pyserial flask numpy
  2. 2
    Flash the Arduino sketch

    Open arduino/servo_serial/servo_serial.ino in the Arduino IDE and click Upload. Or use the command line — the script can re-flash automatically using arduino-builder and avrdude.

  3. 3
    Check the serial port appears
     terminal
    ls /dev/ttyUSB*

    You should see /dev/ttyUSB0. If not, the CH340 driver may not be loaded — the script attempts to load it automatically on startup.

  4. 4
    Grant yourself serial port access
     terminal
    sudo usermod -aG dialout $USER

    Log out and back in once for this to take effect.

  5. 5
    Test it
     terminal
    python3 face_track.py --camera 0

    A window opens with a green dot tracking your nose tip. Press Q to quit.

How to run

Pan only — 1 servo

 terminal
python3 face_track.py

Pan + tilt — 2 servos

 terminal
python3 face_track.py --tilt

Pan + tilt + jaw — all 3 servos

 terminal
python3 face_track.py --tilt --jaw

Headless with IP camera (no monitor needed)

 terminal
python3 face_track.py --network 192.168.1.181 --no-display --tilt --jaw

If servos move the wrong direction

 terminal
python3 face_track.py --flip       # invert pan (left ↔ right)
python3 face_track.py --flip-y     # invert tilt (up ↔ down)

Face parameters

Calculated every frame from camera landmarks. All values are 0–99 (directional ones are −99 to +99). Shown live on the dashboard.

x
0 – 99  (left → right)
Nose horizontal position. 50 = centre. Drives the pan servo.
y
0 – 99  (top → bottom)
Nose vertical position. 50 = centre. Drives the tilt servo.
mouth
0 – 99  (closed → open)
Lip gap openness. Drives the jaw servo in real time.
distance
0 – 99  (far → close)
Apparent face size. Used to detect approach/retreat gestures.
yaw
−99 – +99
Head turning left or right. Positive = facing right.
pitch
−99 – +99
Head tilting up or down. Positive = looking up.
roll
−99 – +99
Head leaning sideways. Like a curious dog.
left_eye / right_eye
0 – 99
Eye openness. 0 = fully closed (winking), 99 = wide open.
smile_kiss
0 – 99
Mouth shape. Low = pursed lips, high = wide smile.
pan / tilt
0 – 180°
Actual servo angle being sent to the Arduino this moment.
jaw
90 – 150°
Jaw servo angle. 90° = closed, 150° = fully open.

Gesture detection

Each gesture appears as a badge on the dashboard and sends a one-letter serial code to the Arduino — use it to trigger LEDs, sounds, extra servos, anything.

↕ NodG:N
Move head up and down at least twice deliberately
↔ ShakeG:S
Move head left and right at least twice deliberately
📍 ApproachG:A
Move face noticeably closer to the camera
↩ RetreatG:R
Move face noticeably farther from the camera
😮 Mouth openG:M
Open mouth wide — above ~40 on the mouth scale
😐 Mouth closeG:C
Close mouth below ~20 after it was open
💡

Each gesture has a cooldown so it doesn't fire repeatedly. Nod/shake: 1 s. Approach/retreat: 1.5 s. Mouth: 0.8 s. All adjustable in gesture.py.

🎛

Fine tuning

All values live at the top of face_track.py and gesture.py. Edit with any text editor — no recompile needed, just restart the script.

Servo tracking — face_track.py

EMA_ALPHA0.30
How fast the position updates. Higher (0.5+) = faster but jittery. Lower (0.15) = smoother but laggy. This is the main smoothness knob.
ANGLE_SCALE270
Servo degrees mapped across the full camera width. Lower = smaller movements. Higher = bigger sweep. Try 180 or 360.
Kp0.20
Proportional gain — how aggressively the servo chases the target. Higher = faster but may overshoot and oscillate.
Kd0.25
Derivative gain — braking force that reduces wobble. Raise if the servo oscillates back and forth past the target.
SLEEP_AFTER3.0 s
Seconds with no face before servos return to 90° centre. Increase to hold position longer.
SEND_INTERVAL0.10 s
How often commands are sent to the Arduino (10 Hz). Lower = smoother motion, more serial traffic.

Jaw servo — face_track.py

JAW_CLOSED90°
Servo angle when mouth is fully closed. Adjust if the jaw doesn't rest flush against the face on your robot.
JAW_OPEN150°
Servo angle when mouth is fully open. Increase for a wider swing. Decrease for subtler movement. Don't exceed 180°.

Gesture sensitivity — gesture.py

NOD_MIN_AMP / SHAKE_MIN_AMP15
Minimum head movement range to trigger. Lower = fires more easily. Higher = needs a bigger deliberate movement.
NOD_COOLDOWN / SHAKE_COOLDOWN1.0 s
Minimum gap between repeated firings. Raise if a gesture keeps triggering when you didn't mean it.
PROX_DELTA12
How much face size must change to fire approach/retreat. Lower = triggers on smaller movements.
MOUTH_OPEN_THRESHOLD40
Mouth openness (0–99) to fire "mouth open". Raise to 55–60 if it fires while you're just talking.
MOUTH_CLOSE_THRESHOLD20
Mouth openness to fire "mouth close". The gap between 20 and 40 prevents rapid flickering between states.

FAQ

😬 The servo twitches even when my face is still ▶

Lower EMA_ALPHA (e.g. 0.15) to smooth the nose position more before it drives the servo. You can also raise Kd slightly to dampen oscillation.

Some twitching on the tilt axis when you pan is normal — the 2D nose Y-coordinate shifts when the head turns, which is a known limitation of pixel-based tracking.

🔄 The servo moves the wrong direction ▶

Add --flip to invert pan (left ↔ right) or --flip-y to invert tilt (up ↔ down). No hardware change needed.

👄 The jaw servo doesn't move ▶

Check three things: (1) Did you pass --jaw when starting? (2) Was the Arduino re-flashed with the latest sketch — jaw support was added recently and older sketches ignore pin 6. (3) Open the dashboard and watch the mouth value — if it stays at 0, improve lighting so MediaPipe can see your lips clearly.

🔌 It says "ttyUSB0 not found" ▶

The CH340 USB driver may not be loaded. The script tries automatically. If it still fails, run:

sudo modprobe usbserial
sudo bash fix_usb.sh

Then re-plug the USB cable and try again.

📷 Camera not found ▶

Try --camera 0, --camera 1, or --camera 2 — the index depends on which cameras are connected. For IP cameras use --network 192.168.x.x with the camera's local IP address.

🤦 Gestures keep triggering by accident ▶

Raise the cooldown values in gesture.py. For nod and shake, also raise NOD_MIN_AMP / SHAKE_MIN_AMP — this requires a larger, more deliberate head movement before it counts.

📡 Arduino not responding ▶

Make sure no other program (e.g. the Arduino IDE Serial Monitor) is using the port at the same time — only one program can hold a serial port. Also confirm the baud rate is 115200 in both the sketch and the Python script.

🍓 Can I use a Raspberry Pi instead? ▶

Yes — any Linux machine with Python 3.8+ works. The Jetson is preferred because MediaPipe runs faster with GPU acceleration (25–35 FPS). A Raspberry Pi 4 will get around 10–15 FPS, which is still functional for smooth servo tracking.

🛠 How do I add custom reactions to gestures? ▶

In servo_serial.ino, find the handleGesture(char code) function. Each gesture sends a single letter: N nod, S shake, A approach, R retreat, M mouth open, C mouth close. Add LEDs, a buzzer, NeoPixels, extra servos — anything — inside that function based on the code received.

⚡ What FPS should I expect? ▶

Jetson Orin Nano: typically 25–35 FPS with the face mesh model. Raspberry Pi 4: around 10–15 FPS. The servo update rate is capped at 10 Hz regardless of camera FPS — so even at 15 FPS the servos still move smoothly.
